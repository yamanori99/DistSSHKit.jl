hosts

Lab inventory and DistSSHKit pool on the queue host. These verbs do not enqueue. Not --hosts (that still names workers on go / ride / drive). Queue has no hostinfo and does not special-forward it.

julia -m DistSSHKit qhost add-host parent child:host1
julia -m DistSSHKit list-host
julia -m DistSSHKit qhost pool
julia -m DistSSHKit qhost remove-host child:host1

From a client, list-host and pool are forwarded like status. add-host / remove-host run on the queue host only (like setup). add-host and pool compare each worker's Julia with the running serve, or with the next serve's Julia from the enable unit. They warn when major.minor, the patch, or the prerelease differs. A build-only difference does not warn. When serve's Julia cannot be read, they say so and do not compare. When there is no serve and no enable unit, they also say to start serve, or enable, so the next add-host or pool can compare. Both commands still exit 0. The warning's next line is qhost up. DISTSSHKIT_QUIET hides the lines. This is not setup --check: that check compares a worker with the Julia that runs the check.

Also: Prepare, submit, kit hostinfo, kit pool.

add-host / remove-host

Write host tokens into config hosts (parent[:N] / child:NAME[:N]). parent is slots on this queue host, not an SSH Host named parent. child:NAME is SSH Host NAME. add-host child: prints a warning: anyone who can submit as this queue-host user (including qhost:) can use those names via DistSSHKit (DISTSSHKIT_QUIET hides it). A second line: those hosts need outbound internet for instantiate unless the Julia depot already has the registry and packages. SSH/rsync success is not enough if instantiate still has to fetch. A nonempty ~/.julia is not that test. See Requirements (one trust domain). Optional :N is a per-name max.

Missing hostsNamed tokens error unless leftover allowed (add-host first)
First add-hostCreates hosts
hosts = []Last remove-host; submit accepts none
Leftover allowedInventory until add-host rewrites it to hosts

No serve restart. Next submit re-reads the file. A job that is already :running is not stopped.

list-host

Read-only. One row per host: NAME / TOKEN / MAX / JULIA / SSH. NAME for parent is this queue host's hostname; TOKEN stays parent (copy-paste for submit, including parent:N). Children: NAME is the SSH Host, TOKEN is child:NAME. JULIA is that host's juliaup default patch (1.12.7 from the * Version column); - if juliaup is missing, SSH or status fails, or there is no Version on the * row. SSH is this machine locally, queue host via qhost:, else user@hostname from ssh -G (:port when not 22). No private keys or IdentityFile. ssh -G runs on the queue host. NAME is still the queue host's hostname, not the client's.

julia -m DistSSHKit qhost:HOST list-host

pool

pool wraps the same pool on the queue host (cwd / project). Cores / RAM / reachability (no worker-count hint). Missing facts print as -, not 0. Omit tokens: config hosts are passed. Does not enqueue. Same nesting as submit: the verb, then host tokens. Enqueue with the same :N on every config host is submit pool:N (submit). size is gone; Queue rejects it.

julia -m DistSSHKit  [qhost:HOST]  pool  parent  host1
└── Julia ──┘  └── queue host ──┘  └─ pool ┘  └──── host tokens ────────┘
julia -m DistSSHKit qhost:HOST pool
julia -m DistSSHKit qhost:HOST pool parent host1

Flags: pool. help qhost pool adds a note under that command's help.
